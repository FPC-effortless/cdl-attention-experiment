# CASM-X14 — Explicit soft occupancy-state allocation

## Status and purpose

CASM-X14 is preregistered before implementation or execution.

X13 separated two mechanisms. The logarithmic collision barrier repaired X12's saturation-sensitive seen optimization for the independent scorer: every independent-barrier seed was exactly competent at trained `n=2,3,4`. However, all three seeds failed at unseen `n=5,6`: the first four variables retained distinct sharp assignments, while newly introduced variables mapped sharply onto already occupied slots.

This makes another penalty change poorly targeted. X14 instead tests whether the missing ingredient is explicit generated resource state inside the allocation computation.

X14 keeps the X13 barrier, descriptors, executor, supervision, train/unseen cardinality split and optimizer. It replaces the one-shot per-variable binding map with a fixed-depth, differentiable, permutation-equivariant refinement process that can read the slot occupancy generated by its own current soft binding.

## Question

> Is explicit soft slot-occupancy state sufficient to turn X13's seen-only injective allocation into an allocation procedure that remains collision-free and executable at unseen cardinalities under answer-only supervision?

The intended mechanistic contrast is occupancy-aware iterative allocation versus a parameter-identical iterative allocator whose occupancy channel is ablated.

## Frozen allocator

Retain the X10/X13 deterministic external-variable descriptors and candidate-slot descriptors unchanged.

A shared relational base scorer produces initial logits `L^0 ∈ R^{n×8}` exactly from external/slot descriptor pairs. No learned parameter is indexed by external-variable identity, active cardinality or candidate-slot identity.

Define `P^t = softmax(L^t, dim=slot)`.

For each row `i` and slot `s`, define generated other-row occupancy:

`O^t_{i,s} = sum_{j != i} P^t_{j,s}`.

A shared cell-wise refiner receives only:

- base logit `L^0_{i,s}`;
- current logit `L^t_{i,s}`;
- own current probability `P^t_{i,s}`;
- generated other-row occupancy `O^t_{i,s}`.

The refiner is the same MLP for every row and slot and returns a scalar residual `Δ^t_{i,s}`.

Update:

`L^{t+1}_{i,s} = L^t_{i,s} + Δ^t_{i,s}`.

Freeze **8 refinement rounds**, anchored to the already supplied eight candidate slots rather than train or evaluation cardinality.

The final binding is `softmax(L^8)`.

No target value, hidden state, semantic label, correct assignment, matching solution or oracle topology enters the refinement computation.

This is an explicit resource-state prior. Success would not constitute spontaneous ontology discovery.

## Regimes

Four regimes receive identical task batches and optimizer schedules:

1. `canonical_functional` — deterministic positive control.
2. `x13_one_shot_barrier` — exact X13 independent relational scorer with the X13 row-spread + logarithmic barrier objective, on new seeds.
3. `iterative_no_occupancy` — new 8-round refiner; its occupancy input is clamped to zero at every round.
4. `iterative_occupancy` — parameter-identical 8-round refiner with the generated `O^t` channel active.

The two iterative variants begin bit-identically, have identical parameter counts, receive identical batches, and differ only in whether generated other-row occupancy is exposed to the refiner.

The one-shot baseline remains present to verify that X13's every-seed seen competence replicates on the new seed set and to localize any iterative-architecture optimization failure.

No regime uses hard masks, hard injectivity, Hungarian/matching, Sinkhorn projection, sorting-based assignment, collision repair, target assignment, binding labels, teacher forcing, intermediate-state supervision or hidden-state targets.

Hard evaluation remains independent row argmax with collisions observable and unrepaired.

## Permutation requirement

The iterative allocator must remain equivariant to arbitrary permutation of external rows and arbitrary permutation of candidate-slot columns when their descriptors are permuted consistently.

`O^t` is a symmetric sum over other rows, and the refiner is shared cell-wise, so row presentation order must not become an allocation prior.

## Frozen structural objective

Retain X13 exactly:

`R_spread(B) = mean_i H(B_i) / log(8)`

and with `epsilon = 1e-3`:

`R_barrier(B) = mean_{i<j} -log(1 - (1-epsilon) * dot(B_i,B_j))`.

All learned regimes use:

`L = L_answer + R_spread + R_barrier`

with coefficients `1.0` and `1.0`.

No quadratic-capacity regime is needed in X14 because X13 already resolved that seen-optimization comparison. X14 isolates allocation state.

## Frozen data / executor / optimization

Retain X13/X9R2:

- task-supervised train cardinalities `n ∈ {2,3,4}` only;
- deterministic `2,3,4` repeated schedule;
- train depth `8`;
- batch size `128`;
- `10,000` optimizer steps;
- fixed final external register `0` is the only task target;
- no teacher forcing;
- no intermediate/hidden targets;
- no semantic operator labels;
- eight candidate slots;
- X9R2 slot-identity-invariant local executor;
- AdamW, weight decay `1e-4`;
- cosine LR `2e-3 -> 2e-4`, no warmup;
- global gradient clipping `1.0`.

There is **no training loss of any kind at `n=5,6`**. In particular, the barrier is not evaluated on unseen cardinalities during optimization.

Evaluation remains separate for `n=2..6` at depths `8,12,24,48,96`, `eval_n=256`, with soft binding and unrepaired hard binding.

## Integrity requirements

Before training, tests must establish:

1. inherited X9R2 slot-permutation equivalence;
2. unchanged X13 external and slot descriptor definitions;
3. no learned external-ID, cardinality-ID or slot-ID embedding/table;
4. `iterative_no_occupancy` and `iterative_occupancy` are bit-identical before optimization;
5. the iterative pair has exactly equal total/trainable parameter counts;
6. the one-shot X13 baseline retains the exact X13 barrier formula and coefficients;
7. the iterative pair uses exactly 8 refinement rounds;
8. generated occupancy equals `sum(other rows)` of the current soft binding;
9. a row never contributes to its own `O^t` value;
10. `O^t` is invariant/equivariant under external-row permutation as mathematically appropriate;
11. the complete occupancy-aware binding function is external-row permutation-equivariant;
12. the complete occupancy-aware binding function is candidate-slot permutation-equivariant when slot descriptors are permuted consistently;
13. the no-occupancy variant clamps only `O^t` to zero and otherwise executes the same refinement network/round count;
14. changing another row's generated probability can affect a focal row through the occupancy channel in the occupancy-aware variant under a nondegenerate refiner configuration;
15. the same intervention cannot affect the focal row through cross-row occupancy in the no-occupancy ablation;
16. gradients from the X13 structural objective reach both the base scorer and refiner parameters;
17. structural/refinement computation reads only generated descriptors/binding state;
18. changing hidden/intermediate targets or semantic labels while preserving final register-0 target leaves losses unchanged;
19. changing final register-0 target can change answer/total loss;
20. no hard mask, injectivity, matching, Sinkhorn, sorting assignment, collision repair or target assignment is used;
21. hard collisions remain observable under independent row argmax;
22. all regimes receive identical batches and optimizer schedule;
23. training schedule is exactly `2,3,4` repeated;
24. no train-time forward/loss call is made at `n=5,6`;
25. training aborts on non-finite/negative answer loss or non-finite total loss.

## Frozen interpretation

### Positive-control prerequisite

`canonical_functional` must satisfy every seed and every `n=2..6`:

- hard answer-final >=99% on every suite;
- hard deep step-state exactness >=95% at depths 24/48/96;
- hard deep hidden-register accuracy >=99% at depths 24/48/96.

Failure invalidates X14.

### X13 replication prerequisite

`x13_one_shot_barrier` must satisfy seen-cardinality competence on every new seed at `n=2,3,4`. If it does not, the new seed set fails to replicate X13's seen result and the X14 occupancy comparison is interpreted cautiously.

### Seen-cardinality competence

A learned regime is unseen-eligible only if every seed at `n=2,3,4` has:

- hard and soft answer-final >=99% on every suite;
- hard and soft deep step-state exactness >=95%;
- hard and soft deep hidden-register accuracy >=99%;
- exactly `n` unique hard-argmax slots;
- zero collisions;
- mean row maximum >=0.90.

IID depth-8 answer-final <80% on any seen cardinality is optimization failure.

### Strong unseen-cardinality generalization

A learned regime passes strongly only if every seed at both `n=5,6` has:

- hard and soft answer-final >=99% on every suite;
- hard and soft deep step-state exactness >=95%;
- hard and soft deep hidden-register accuracy >=99%;
- exactly `n` unique hard-argmax slots;
- zero collisions;
- mean row maximum >=0.90.

No averaging rescues a failed cell.

### Partial unseen generalization

If strong fails but every unseen cell has answer-final >=90% and deep step-state/hidden-register >=80%, classify partial and report the boundary.

### Occupancy-state effect

A causal occupancy-state claim is eligible only if **both iterative variants satisfy seen competence on every seed**.

If eligible:

- if `iterative_occupancy` passes strong unseen on every seed and `iterative_no_occupancy` does not, explicit generated occupancy is supported as the decisive extrapolation treatment under this allocator;
- if both pass strongly, occupancy is not necessary under the iterative architecture;
- if both fail unseen, 8-round explicit occupancy is insufficient;
- if occupancy is partial and no-occupancy fails partial, report a partial extrapolation improvement only;
- if the no-occupancy ablation fails seen competence, the causal extrapolation comparison is ineligible because iterative architecture and optimization are confounded;
- if occupancy itself fails seen competence, classify occupancy optimization failure rather than evidence against resource-state usefulness in general.

### Relation to one-shot X13

If one-shot and no-occupancy both replicate X13's seen competence but fail unseen while occupancy passes strongly, the cleanest supported claim is:

> Under the frozen X13 barrier and descriptors, carrying generated soft resource occupancy through a shared permutation-equivariant allocation computation enables cardinality extrapolation that one-shot and occupancy-ablated allocation do not.

Do not generalize beyond this controlled world.

## Successor boundary

Only a strong unseen-cardinality PASS authorizes the next experiment to remove supplied active cardinality or external-variable identity. Otherwise work remains inside binding-allocation learning.
