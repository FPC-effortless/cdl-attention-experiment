## Interpretation and limits
- Convolution receptive field = 1 + 2*(1+2+4) = 15 tokens; the cache retains 14 tokens. Query encoder consumes 14 suffix + 5 question tokens. Causal filters see no future observations.
- append(raw_text) updates an actual persistent posting index. query(question) reads it without rebuilding or modifying history, unlike convenience route(full_document). This changes end-to-end repeated-query cost from O(full history) to O(question length + fixed 15-token receptive field + result size), subject to amortized ingest; memory and write cost remain O(history length).
- This benchmark only demonstrates CPU query-cost improvements on one trained seed and restricted synthetic sentences. P95, hardware variability, concurrent queries, real language tokenization, GPU throughput and multi-seed accuracy remain unestablished.
- The cache uses a **supplied question boundary**: calling query() is itself a structural prior. It neither discovers natural questions nor resolves pronouns.
- Critically, the wrong H=6 answer and earlier seed23/OOV failures remain. Faster incorrect retrieval is not a capability gain.

## Decision
Preserve as a valid isolated stateful efficiency demonstration. Do not promote an overall language-model replacement claim or merge into the model backbone. The next bottleneck is robust learned relation semantics and calibrated abstention, not hash lookup.
