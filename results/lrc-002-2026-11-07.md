# LRC-002: oracle decoding passes; learned routing remains unqualified

2026-11-07. Prospective controlled diagnostic, not an architecture superiority result. Source and protocol were published at `d298a9a45aea02e3da86f270acfc6c060eddb615` before fitting. All 18 fits closed before held-out evaluation. No post-result retraining or threshold changes.

## What the attachment contributed

The compression discussion motivated measuring how much answer uncertainty memory removes, separately from predictable text patterns. We report negative log probability in bits per complete answer. This is a model prediction metric, not a measured archive size, mutual information estimate, or proof that memory overhead is repaid. Details and corrected information-theory qualifications are in the [protocol](../relational_composition/EXPERIMENT_LRC002.md).

## Prespecified gates

- **Oracle endpoint decoder competence: PASS 3/3.** Answer-focused oracle achieves 64/64 IID greedy answers in every seed (required >=90% in every seed).
- **Random-label leakage alarm: NOT TRIGGERED.** Exact answers are 3/64, 2/64, 2/64 (alarm threshold >20% in any seed). Mean answer loss 4.4279 bits is near the specified uniform-20 population entropy of 4.3219 bits. Passing this control does not prove absence of every possible leak.
- **Architecture qualification: NOT ESTABLISHED.** Learned routing has 6.25% mean IID accuracy versus 5.21% for the separately trained local LM. No superiority test or coupling qualification is claimed.

## Interpretation

1. The neural operator can decode the answer from supplied supporting endpoints on the trained alphabet. Oracle routing already resolves the relation chain, so its 100% held-out-order score is not evidence of learned multi-hop composition.
2. Even with correct endpoints, full-text LM training reaches only 58.85% versus 100% under answer-focused training at the same update budget. Loss weighting and optimization remain relevant alongside route discovery. This does not isolate a unique causal explanation.
3. The learned router has negligible corruption sensitivity (mean about 0.012 bits/answer) and near-local answer performance. Lower whole-text loss still does not establish meaningful relational memory use.
4. Every arm scores 0% on unfamiliar names. **This population changes identifier suffix characters, not just name combinations.** It therefore confounds identity generalization with generating characters absent from name targets during training, and cannot isolate cross-mention binding failure. Preserve the negative result; replace this axis in a future protocol with unseen multi-character identifiers made from the same trained alphabet, plus a separate genuinely new-character stress test.
5. The answer-only oracle has poor whole-text NLL (about 6.26): its narrow success is not a usable language model. All exact-answer figures use generated feedback; teacher-forced figures are separately retained.

## Next research decision

Keep the architecture unchanged. Before another architectural comparison, test whether outcome-based routing credit can improve on the trained local baseline while preserving raw-text learning. Separate that from an explicitly answer-supervised diagnostic; do not present answer masks as unscaffolded language learning. The next protocol should also repair the name split and include a copy-capacity control. Use new seeds/worlds and specify competence before comparing coupling versus independent decisions. No follow-on fit was performed after these results.
