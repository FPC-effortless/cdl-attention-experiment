# nanoCOG communication reference: finite grouped packets

## Source alignment

The adapter target is nanochat's pinned master commit `92d63d4e8bb4df75c3b71618f31ddde2378b2bcd`, especially [gpt.py](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/gpt.py), [engine.py](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/nanochat/engine.py), and [base_train.py](https://github.com/karpathy/nanochat/blob/92d63d4e8bb4df75c3b71618f31ddde2378b2bcd/scripts/base_train.py). Stock GPT expects causal attention's projected delta inside the enclosing residual, mutable per-layer KV buffers, and one last-layer position advance. The stock generation engine prefills one row, replicates it for sampled forks and feeds the returned cache into token-at-a-time generation. This module fits the *delta interface*, not stock KV methods. No upstream source is copied here.

The independently audited COG-PULSE-006 report and original native code motivated the design: there are distinct publish, writer topic, subscription, broker, commit/address and later read operations; published observations were available to same-event subscribers in that experiment. Publication was about 98.9% and current-event delivery about 98.2%, despite essentially no reliable custody-revision success. The direct current-sentence bypass improved joint write accuracy 38.77%→43.44%, not the preregistered pair answer gate (6/2,400→8/2,400). Higher delivery or gate activation is therefore not itself a competence criterion. Separate stable record identity from mutable stored values for any downstream committed state; this packet module is a transient carrier, not an authoritative state board or a replacement for that study.

## Semantics

At step t, x contributes immediately through a learned depthwise lag mixer plus a channel projection. For each group g, x also scores separate top-one write and read topics in a learned codebook. The supplied cache contains only previous *valid* steps: compute read and local contribution first, then update the selected writer bucket only if its learned publish logit is nonnegative. Each topic has fixed FIFO depth K; learned admission controls what enters and learned age weighting controls the readout, **not** exact or learned eviction. Empty subscriptions produce a zero packet. Learned output gains are initialized small nonzero (gain additive bias −2), not a forced utilization floor. Pad tokens change no state/count, and produce exact zero delta. Current x cannot publish to its own packet read; unlike the original PULSE order, its same-step path is exclusively the local branch. No content-dependent pairwise token attention or walk over an unbounded history is used. Training applies a dense *fixed-topic* straight-through surrogate, not an independently verified routing-gradient theorem or a claim of sparse backpropagation.

`PacketCommunication(width, groups=4, topics=8, packet_width=16, capacity=4, local_window=4)`
- `delta, state = layer(x, state, valid=mask, return_state=True)` for B,T,C x and Boolean B,T mask. State may be None for a cold start. If `return_aux=True` the final output is a dict with publish logits, routes and hard commits for explicitly scoped diagnostics. No in-module residual, norm, head or answer metadata. `use_packets=False` is a same-weight hard packet ablation, not a separately optimized local-only serving baseline.
- Functional inputs are not mutated. `state.index_select(rows)` independently clones row storage (including duplicate indices) for prompt forks; `reset_rows(mask)` cold-starts chosen rows. `state.detached()` clones and detaches the full state. `state.positions` counts valid steps independently per layer; the engine should maintain its own externally consistent position **once after all layers**, never advance each layer again. Carry the preceding-token embedding/whatever additional state nanochat's mixer needs separately through the same fork/reset. Serialize layer tensors with explicit shape/dtype and version metadata when implementing durable continuation.
- `layer.step_inplace_(x, owned_state, valid=mask)` mutates caller-owned storage only in `eval()` plus `torch.inference_mode()`. No alias to a source prefix may remain; fork first, never use an expanded view. Deployment preferably uses this path to avoid full topic-state copying each token. Ordinary evaluation under no-grad uses indexed reads/writes with functional copies; eval with gradients uses hard-routing dense path without learned routing backward rules.

## Cost and limitations

Let B be batch, G groups, A topics, K depth, D packet width, W local window, C residual width, s stored scalar bytes. State exactly `B * s * (G*A*K*(D+1) + (W-1)*C) + 8*B` bytes per layer, excluding parameters, transient activations, allocators and other engine state. State bound is independent of total prefix length; information can be evicted, and collisions have no explicit identity/version protection. Retained payload scan is K rows in a selected topic per group, but destination logits/argmax still evaluate A routes and all groups. Conditional writes currently do same-shape gather/where/scatter even on rejected writes, so a low logical publish rate does **not** automatically save wall time. Functional decode copies the entire packed state once per call. Training visits all G*A*K buckets and autograd can retain O(T B G A K D) intermediates; the Python temporal loop, sequential writes and materialization are expected bottlenecks. No measured speed/quality advantage vs fused nanochat or SSM. A schedule mismatch is also possible near hard argmax/threshold ties under different floating-point GEMM batching; qualify platform/precision-specific route agreement rather than promising bit-exact cross-device replay.

Keep nanochat tokenizer/residual/FFN/head/optimizer opportunity fixed and compare (i) upstream GPT attention, (ii) separately trained local-only mixer, (iii) packet learned routing, (iv) fixed/hash/random route at matched state+budget, (v) same-weight packet-disabled and target-versus-matched-foil publish suppression/reroute. For matched resource accounting report active+total parameters, consumed bytes/tokens, training cost, read/write and idle/no-op counts, routing concentration, candidate collisions/coverage, age and eviction-survival histograms, full prefill/decode cache-fork/reset latency, and peak/retained memory. Tie packet recall to paired *correct outputs*, current versus stale value, and third-entity invariance; coverage alone is not competence. Test collision/overwrite under new timing + typed and separately real-language versions; avoid funding scale based on oracle or short easy panels. Apply the 12:1 cost objective only after quality gates at matched inference boundary.

## Engineering checks (not trained evidence)

One CPU thread and Torch 2.10.0+cpu: run `python -m unittest -v nanocog.comm.test_packet` from the package parent. Eight tests check prefix invariance, empty first packet read and same-step causality, padding with contaminated invalid tokens, streaming/chunk and indexed-vs-STE path parity, prompt fork/reorder/reset, exact FIFO depth, model gradient connectivity, state-byte bound and owned-mode protection. These are random weights and inert synthetic tensor fixtures, not learning, benchmark TEST, or a comparative timing result.
