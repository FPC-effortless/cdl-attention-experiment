# ASSOC-002 development panel — selective retrieval under noisy cues

## Source and scope

The supplied UNIFIED-001 report describes three seeds, 4,464 grounded tasks, 2,502 new-entity tasks, 1,296 procedural checks and a 3.18× fused-versus-interpreted speedup. It reports four-cue Hebbian communication accuracy of 100%, 93.75% and 4.56% at 29, 64 and 256 associations, with 100% for growing retrieval at each load. The report describes 13 byte-reproducible evidence files, 24,300 commutativity checks and nine affine-prefix panels. Its package and manifest were unavailable in this workspace. These are author-reported results. The proposed sequence prioritizes ASSOC-002, then semantic grounding, autonomous skills, native parallel execution and verification, neural integration and resource-matched architecture evaluation.

## Prospective engineering diagnostic

Use three construction seeds (11, 23, 37) and the three reported loads. Draw independent unit keys in 64 dimensions and distinct eight-bit bipolar payloads. A four-cue packet is correct if all four decoded payloads are exact. Use 512 independent packets per seed and load with fresh Gaussian noise (standard deviation 0.09 per coordinate before normalization). Compare normalized-key Hebbian writes, one-pass delta writes, full nearest neighbor, an eight-bank sign-bit index, and a hybrid which first reads delta memory and queries the indexed store on low confidence. Calibrate the confidence threshold on a separately generated store and packets, permitting at most 50% external lookups there. Record observed lookup rate and accuracy on evaluation packets. Use the first three key coordinates to address banks and probe the two nearest sign regions (query bank and flip least-certain bit). Cap candidate comparisons at 32 per query in insertion order. Include an equally sized random candidate control. Report the mean number of candidates actually compared, allocated numeric state and construction assumptions. This standalone diagnostic measures implementation behavior and exposes routing failures before specifying a claim-bearing CSM protocol.

## Internal review

A separate Codex scientific-review subagent reviewed the design before execution. Its review called for disjoint calibration stores, clean and incorrect-binding controls, identical packets across arms, explicit memory accounting, and seed-level results. Calibration and evaluation use separate RNG streams; payloads are sampled without replacement within each store, from the same eight-bit vocabulary across stores. Four targets are sampled with replacement in each packet. Clean keys must recover their exact nearest neighbor. The negative control cyclically shifts every retrieved row's binding. Empty candidate sets abstain. Ties use first occurrence. The hybrid returns the indexed result below the calibrated threshold and otherwise returns the delta read. At loads above the search cap, insertion order can disadvantage late writes. Counts report logical candidate dot products (64 dimensions), excluding routing overhead and the additional 8×64 read per hybrid cue. Memory counts cover numeric persistent arrays including index entries; interpreter overhead, temporary buffers and the scalar threshold are excluded. The banked and delta arms are the always-lookup and never-lookup controls. All arms are evaluated together for paired comparisons.
