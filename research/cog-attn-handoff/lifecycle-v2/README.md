# COG-ATTN epistemic lifecycle v2 — 042d, 042e, 037b

CPU Python diagnostics, no neural training, authentic interaction or upstream trained-model integration. Prospective primary protocol and follow-up protocol are included. Primary and replication panels each have 32 seeds; follow-up uses 64 new seeds. All deterministic outputs in both files replayed exactly excluding timing fields. Replays are same-code re-execution, not independent implementations. Timing aggregates are illustrative and machine-dependent.

## 042d: risk-sensitive audits
Eight binary latent sources flip independently, and one uniformly sampled source is read each command. An exact source-specific independent anchor is assumed. All arms receive identical query streams and audit times, with 64 or 128 anchors over 2,000 steps. Severity and nominal hazard are supplied; empirical estimates use disagreement counts divided by elapsed exposure with a prior, which undercounts even-numbered flips. The risk heuristic prioritizes age times square-root(weight × nominal hazard). No direct access to truth except audit. Accuracy is unconditional: no abstention policy.

At 32 audits/1,000, mean weighted loss: uniform 2615.28125, criticality 1934.28125, risk 1690.0625, adaptive 1697.015625. High-criticality accuracy 73.49%, 81.71%, 85.31%, 84.92%, respectively. Risk reduction 31.36% and 39.15% in primary and replication, passing >=20% gate. Overall accuracy 86.53%, 87.16%, 86.31%, 86.34%. At 64 audits/1,000 uniform 1580.125 vs risk 973.96875. Under reversed hazard ordering at 32, uniform 771.84375 vs risk 792.46875; at 64, uniform 440.828125 vs risk 535.78125. Thus no universal superiority. The risk policy's longest interval reaches 1,344 commands, versus uniform 250 at 32/1,000.

Fresh follow-up at 32: nominal weighted loss uniform 2457.72, risk 1668.39, deadline 1938.95, half-uniform mixture 1886.86. Max observed audit intervals 250, 1344, 469, 500. With reversed hazards loss 640.25, 715.55, 713.39, 686.53. Deadline/mixed retain some nominal gains but neither beats uniform in stress. No guarantee of max age or absolute safety. Objective weights and hazards are synthetic policy inputs; no actual sensor cost or learned risk estimator.

## 042e: automatically traced provenance
256 derivations per seed trace branch selector, selected read, nested subprocedure reads and external read. Independently specified fixture gold sets are asserted equal to recorded trace keys. 16 sequential source changes per seed evaluate all original snapshots, yielding 262,144 record-change checks (122,739 affected and 139,405 unaffected). Direct-only manual control misses 90,101 affected; trace misses zero, false invalidations zero. Deliberately untracked external dependency misses 17,371. Simulated reverse lookup excludes the current changed source's path, leaving 13,177 stale instances not caught eagerly; independent epoch guard catches all. This is an omission simulation rather than a real reverse-index implementation. Source epochs change but values are not mutated in this fixture; affected is conservative provenance validity, not necessarily a wrong numeric value. 4,096 simulated changes between read and commit: unguarded always admits, guarded none. No threads or atomic commit implemented; production needs atomic snapshot/validation and transitive mediation. The trace class is intentionally naive when a key is reread; the follow-up arithmetic counterexample shows last-read overwrite accepts 8,192 mixed-epoch snapshots, first-read/conflict check accepts zero, while stable snapshots pass 8,192. A cached path may depend on its selector; unexecuted branches are not certified. No guarantee for reads outside instrumentation, external side effects, or mutable dependency metadata.

## 037b: incremental compilation
Affine operators modulo 65521, 1,024 steps and 128 source keys. Segment tree stores composed operators; inverse mapping from operator key to leaves. Recompile affected ancestors, retaining unaffected subtrees. Full baseline sequentially composes latest operations. Per seed, 12 events at each of 1, 8 and 32 key changes. All 2,304 root and independent sequential-state comparisons equal; 192 structure insertions followed by full rebuild also match. No stale read allowed before repair. Aggregate time in results.json includes full initial fold vs tree construction plus 12 repairs; timings vary on replay. Primary singleton ~2.98×, replication ~2.71×; gate >1.5× both. Dense changes lose to full fold. No arbitrary nonlinear compilation claim.

Fresh follow-up groups eight single-key updates before each query. 1,024 query checkpoints match (eager, deferred repair, full fold). Eager visits 526,768 tree nodes; deferred 337,751. Measured 168.73ms eager, 95.98ms deferred, 166.18ms full fold at query, excluding tree construction and output application. No comparison with rebuilding after each intermediate update as the sole baseline; full fold on demand included. Lazy repair requires a pending-change guard, not just stale status. Structure changes trigger rebuild. No full TAC/CSM/LRC integration; these are new standalone algorithms, not original module execution.
