# CSM-PARSER-011: selective carrier with role-conflicting local endings
## Hypothesis and scope
010 carriers preserved values but failed event selection under paraphrase. This prospective study tests whether a larger causal parser context helps discriminate code facts from irrelevant facts with identical local endings. It does not test full native CSM repair or broad language understanding.
All four models share the same exact one-code carrier and five-action interface. Arms: three-byte state-conditioned parser (information-limited reference); 24-byte state-conditioned parser; 24-byte stateless MLP; GRU event parser. Primary equal-context comparison is the two 24-byte models; actual parameter counts disclosed. GRU is a competent recurrent parser control, not the failed010 joint-loss configuration. Every arm receives identical assignment labels and event-only loss. No trained final readout or teacher carrier states. No inference labels, roles, positions, or regular expressions.
## Prospective data contract
Known positive aliases code/secret update the one stored property. Marker/tag facts are distractors and must not commit. Templates use is/set/update. TRAIN excludes (update,code) and (set,tag), but all words/roles occur in other TRAIN combinations. DEV tests these held-out combinations separately and together, both distractor orders, and longer delay. These are compositional combinations of familiar lexical units, not unseen-word semantics or natural-language generalization. Labels come from explicit operation records before rendering, not masks inferred from the final answer.
Every pair has different current-code answers and an identical ending. Irrelevant values are factorially balanced independently of both correct answers. Positive/negative order varies in TRAIN. Role cues lie inside24bytes while the last3bytes of positive and negative value mentions can be identical. Filler lengths vary without changing record meaning. Initial code always exists; absence/abstention, COPY/LINK/DELETE, multiple identities, arbitrary values, and capacity scaling are explicitly excluded.
150TRAINconditions×32pairs; sixDEVpanels×64pairs. TRAIN-probe uses16indices [0,1,2,3,8,9,10,11,20,21,22,23,28,29,30,31] percondition, covering every target×noise value cell and both directed-pair offsets. It is a calibration diagnostic, not a new generalization sample. TRAIN-probe is scored full-state only; DEV retains all3interventions. Evaluation batches up to64histories; deployment timing remains8histories. Frozen split plus zero whole-history and nuisance overlap. No protectedTEST.
