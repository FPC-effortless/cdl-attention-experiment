# CSM-CONDITIONAL-018 prospective protocol (DRAFT, NOT ADMITTED)

Question: after clause isolation, can a learned state-conditioned controller correctly choose conditional writes on its own memory, and does it earn its cost against a local parser with an exact conditional executor?

This is a new bounded constructed TRAIN/DEV study, not protected TEST, real-language qualification, native CSM repair or a new Lean proof. Explicit four-record SET/COPY/LINK/DELETE/QUERY semantics, identity lexer, newline clause reset and punctuation commit guard are supplied.

## Arms and controls
- local_learned: clause-local parser, learned predicate gate without memory features. Negative information control, not a competent memory baseline.
- state_learned: clause-local parser, gate and parse head conditioned on OWN predicted typed state.
- local_exact: same local parser and learned gate head, but conditional commits use an exact comparison of the PREDICTED source/expected payload against OWN memory. This is the competent engineered control; never credit its comparator as learned.
All predict operation, destination, source, new payload and expected payload. All receive parsing and gate auxiliary labels. A gate target is recomputed from each arm's own state using the gold predicate, not gold history state; this avoids inconsistent gate targets after previous errors. Gold fields are used only to form losses, never to execute actions. Report target differences across arms. Free-running discrete execution is non-differentiable; surrogate gate/parser losses do not establish end-to-end credit assignment.

## Data
Four TRAIN structures: direct predicate, linked predicate, snapshot predicate and deleted-source predicate. Two DEV-only structures: link chain and detached alias. Four training wording templates; two independently specified untrained wording templates. DEV reports familiar-structure/familiar-wording, familiar-structure/unseen-wording, unseen-structure/familiar-wording and unseen-structure/unseen-wording separately. Each panel balances each identity role and each expected/new payload marginally using a declared16-pair cyclic roster. Only four value permutations are covered; this is not arbitrary-transition coverage. Names and finite payloads remain familiar; this is structural/wording separation, not unrestricted natural language. Exact normalized programs, text and paired history IDs checked, duplicate structures disclosed. Every conditional pair shares exact conditional clause and suffix but differing preceding effective source values; true and false outcomes balanced. No no-op pair where new value already equals destination. Unrelated records and snapshot/live reference preservation are scored.
