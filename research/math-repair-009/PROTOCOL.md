# COG-MATH-REPAIR-009 — preregistered CPU research campaign

Status before dispatch: candidate development, not scientific qualification. No protected official TEST data accessed. No paid compute, merge or deployment authorized. This public branch contains experimental code only; predecessor weight archives remain in their existing custody. User explicitly requested GitHub Actions for a properly budgeted experiment.

## Primary hypothesis and controls
Train from random initialization at approximately 1.08M parameters: upstream nanoGPT GPT (3 layers, 160 hidden, 5 attention heads, standard 4x MLP; absolute positions), archived role-balanced HH (two layers), archived same-interface RoPE grouped-query A0 (two layers), U (HH plus new learned additive slow and group-consistent reflection channels in both layers), UA (COG then GQA with both side paths), AU (GQA then COG with both side paths). HH/A0 source port verified locally against archived constructors. The new side-state code is a hypothesis, not the same trained temporal weights from REPAIR-006. No fixed gold temporal role gates during pretraining. No candidate is predeclared better than the others. Record all six arms and three paired seeds (9001, 9011, 9029). Parameter mismatch <=1.2% (including embeddings and unused auxiliary tensors); compare actual timing and active parameter gradients rather than assert FLOP equivalence. GPT upstream model commit f08abb45bd2285627d17da16daea14dda7e7253e, MIT. This is a small-scale application of the established nanoGPT/GPT recipe, not a reproduction of published GPT-2 performance numbers.

## Corpus, schedule, custody
WikiText-103-raw-v1, Salesforce/wikitext revision 00aa25585682d4957f9e86edc73f59be7419af99. License CC BY-SA 3.0 / GFDL (dataset card: https://huggingface.co/datasets/Salesforce/wikitext). UTF-8 identity byte tokenizer, 256 IDs. Preserve line contents, insert newline only where row lacks one. Split by top-level article headings, exact content deduplication, group titles; deterministic 1% TRAIN article titles reserved as development, exclude these from training. Official validation is a frozen evaluation panel accessible only after all pretraining fits have reached terminal budget; fail closed on exact content or title overlap with training/development. Official TEST is never downloaded. No source-specific claims that absence of exact overlap proves absence of all near duplicates. Archive source hashes, processed split hashes, document titles/hashes and sample order hashes. Training randomly samples distinct nonoverlapping next-byte windows across the full eligible training article inventory, not a small initial file prefix. Short article tails excluded from fixed-length training windows and counted in the manifest. Full development and frozen validation evaluate every target byte after the first byte of each article, including tails. Byte-level BPB, not word or subword perplexity.

Context 768; global batch16; microbatch4, four gradient accumulations; 8,192 optimizer updates per fit, 100,663,296 target-byte presentations per fit. No replacement of training windows; paired architectures use exactly the same per-seed positions. Four sequential stages of 2,048 updates each. AdamW beta(.9,.95), weight decay .1 on matrix weights, none on vectors, global norm clipping 1, peak LR .0006, 164-step linear warmup, cosine floor .00006. Standard FP32 CPU. Fixed recipe, not architecture-specific hyperparameter optimization. Record learning curves and per-document held losses; no performance claims from a small budget or partially finished stage. All stage artifacts retain model/optimizer/RNG and source/data/order lock. If stage reaches wall-time cutoff, preserve partial checkpoint and report incomplete; do not count or quietly shorten it. Continue only after a reviewed compatible resume path. Independent final evaluator loads hash-verified Safetensors of all terminal seeds, no selection on validation. Paired per-seed document-bootstrap intervals, rank and confidence interval only after all runs pass budget and integrity gates. No claim of equal FLOPs or general superiority from matching parameter/token counts alone.
