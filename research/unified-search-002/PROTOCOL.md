## Search space and provenance
Exact parent core model.py (blob 31c3555521469425d884c700aed01b48c4fab50e), variants.py (blob 76ece3b4c83a30e282141db7a29beecb10a5d41e), exact original UNIFIED-014 protected update scan and dependent functions (source archive pinned). All other code is new. Same 288-token shared embedding, shared recurrent layers and tied decoder for real UTF-8 bytes and synthetic symbolic sequences. Extend vocabulary by 32 reserved symbols; initial common byte embeddings and backbone copied from paired fresh original initialization, shrink FFN width to match ~1.077M total parameters. This is a matched derivative, not an exact replica of original HH/U. No task-selected backbone, external frozen parser, supplied slot ID/roster or oracle during primary learned-access inference. The presence-aware port adds one coordinate per native typed slot, hard update via original 014 exact HOLD/RESET with surrogate gradients; read masks empty slots. The factorized matcher is adapted from 014 max-over-token and sum-over-name-component similarity into two trainable prototype components per latent slot, over the current five-token causal window, learned token relevance and zero-initialized additive score gain. It is not the original roster matcher or a proven natural-language acquisition algorithm. Native recurrence/delta memory preserved. Slow/reflect pathways selected from exact HH/U modular implementation, not replaced by new external networks. Factorized vs native addressing crossed with native vs explicit presence, across NN (HH), SS (slow in both layers), BB (full U), 12 primary arms. One GQA control with same vocabulary and comparable params. Four SS regime controls: native and combined presence+factor each with mixed oracle and fixed-world training. 17 arms x 3 new paired seeds (9501,9511,9529) =51 fits. COG-COGNITION-001 recovered verified source/checkpoints remain private; remapped four-key grammar and new 8-key mutation/composition grammar used prospectively, not a historical reproduction. Other layer patterns from #117 are eligible for later crossovers; contextual routing and retention and optimizers remain separate inputs pending their matched results.
